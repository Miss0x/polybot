## 1. 底线结论

**这条路在科学上可以走得通，但以当前实现方式走不通。**

- IARPA 数亿美元投入验证过：结构化概率预测可以在特定领域比公开预测市场准确 25-35%
- Polymarket 的 Geopolitics 品类 **零交易费用**——这是整个可行性计算的基石
- 当前系统停在半路：信号编码完成，但概率校准、贝叶斯更新、聚合、回测全部缺失

## 3. 学术证据链

### 3.1 IARPA ACE 锦标赛（2011-2015）— 最权威预测能力验证

**来源：** 美国情报高级研究计划局，投入数亿美元，历时4年

| 对比维度 | 量化结果 |
|----------|---------|
| 超级预测者 vs 预测市场 | 准确率提升 **25-35%**（Brier分数） |
| vs 情报界内部预测市场（139个问题） | 提升 **34.7%** |
| vs 期货市场（特定事件） | 优势高达 **66%** |
| vs 拥有机密情报的分析师 | 提升 **>30%** |
| 超级预测者校准分数 | **0.01**（近乎完美；基线0.35） |

**超级预测者工作模式：**
- 每个问题阅读 255 条新闻（普通人 58 条）
- 每个问题更新预测 7.8 次（普通人 1.4 次）
- 使用结构化概率推理，非模糊语言
- 团队聚合+极端化（指数 3.08）

**对 Polybot 的启示：** IARPA 验证了"新闻→事件理解→概率更新→聚合"这个流水线可以稳定战胜预测市场。这是 Polybot 架构的科学基础。

### 3.2 ICBe 国际危机事件本体（Cambridge, 2022）

**来源：** UC San Diego + 剑桥大学出版社，arXiv:2202.07081

- 手工构建的 Ontology（事件类型、Actor、地理标签）比 NLP 自动抽取的召回率与精确率都更高
- 将国际危机抽象为"棋子（Actor）× 走法（Event）× 策略（Context）"
- 演示了古巴导弹危机和克里米亚案例，Ontology 优于 CAMEO/ICEWS

**对 Polybot 的启示：** 当前使用的 Ontology 映射矩阵在学术上有明确对应，不是凭空创造。

### 3.3 LLM 校准问题调查（NAACL 2024）

**来源：** TU Darmstadt + MBZUAI

| 发现 | 数值 |
|------|:---:|
| GPT-3/3.5/Vicuna 平均预期校准误差（ECE） | >0.377 |
| GPT-4 用自报置信度区分对错的 AUROC | **62.7%**（接近随机） |
| 模型置信输出集中在 90-100%，与准确率无关 | 系统性偏差 |

**对 Polybot 的启示：** 用 LLM 直接输出概率并以此做交易决策（竞品主流做法），底层信号严重失真。Ontology 规则引擎避开了这个系统性陷阱。

### 3.4 PolyBench（arXiv:2604.14199, 2026）

**来源：** 评估 7 个顶级 LLM 在 38,666 个 Polymarket 市场的表现

| 模型 | 方向准确率 | CWR | 盈利？ |
|------|:---:|:---:|:---:|
| MiMo-V2-Flash（开源） | 62.1% | +17.6% | ✅ |
| Gemini-3-Flash | 75.0% | +6.2% | ✅ |
| DeepSeek-V3.2 | 53.5% | -11.4% | ❌ |
| GPT-OSS-120B | 58.0% | -17.8% | ❌ |

**关键发现：**
- 7 个顶级 LLM 中仅 2 个盈利
- 75% 准确率的 Gemini 赚不过 62% 的 MiMo → 概率校准 > 准确率
- 所有模型平均置信度 0.8-0.9，但多数亏损 → 系统性过度自信
- 政治领域是 LLM 表现最好的类别

### 3.5 Polymarket 平台精度（Fensory, 2026）

**来源：** 分析 2,847 个已结算市场

| 品类 | 准确率 | Brier分数 |
|------|:---:|:---:|
| 政治（二元） | **81%** | 0.164 |
| 全平台平均 | 73% | 0.187 |

**系统性偏差（可套利）：**
- Favorite-longshot bias：概率<10% 的事件实际发生 14%
- Recency bias：重大新闻后 72 小时市场过度反应

## 4. 数学可行性

### 4.1 费用结构

| 品类 | 往返费率 | 盈利所需最低Edge |
|------|:---:|:---:|
| Geopolitics | **0%** | >价差（~1.5%） |
| Politics | 2.00% | >2.0% |
| Crypto | 3.60% | >3.6% |

**伊朗市场属于 Geopolitics，零平台费用。这是关键的可行性前提。**

### 4.2 盈亏平衡

```
E[Profit] = V × (2p - 1) - V × 价差

当价差≈1.5%：盈亏平衡 p = 51.5%
```

**仅需比随机好 1.5 个百分点即可回本。**

### 4.3 Kelly 仓位

```
f* = p - (1-p)/b，二元市场 b≈1

p=55%  → f* = 10%
p=53%  → f* = 6%
```

小 edge 仍然允许非零仓位。

### 4.4 贝叶斯更新（缺失的核心）

当前 Ontology 输出 `direction + strength`。需要改为：

```
先验: P(event) = Polymarket 市场价
似然比: LR = P(signal | event) / P(signal | ¬event)
后验: odds_post = odds_prior × LR
后验概率: P(event | signal) = odds_post / (1 + odds_post)
```

Likelihood Ratio 需要从历史数据中校准——这是下一步的核心任务。

## 5. 三条技术路线

### 路线 A：纯规则引擎（当前）

```
新闻 → 关键词匹配 → ontology查表 → direction+strength → 告警
```

- 优点：极快、确定性、零LLM成本、可解释
- 缺点：覆盖度低（14种事件类型）、无概率校准、无法量化edge
- **评估：** 作为信号发现工具可用，作为交易决策工具不完整

### 路线 B：纯 LLM 推理（竞品主流）

```
新闻+市场描述 → LLM → "YES概率65%" → 对比市价 → 下单
```

- 优点：覆盖度极高、零人工维护、灵活
- 缺点：概率校准差（AUROC 62.7%）、确定性差、成本高
- **评估：** PolyBench 证明可能盈利但不稳定

### 路线 C：Ontology 编码 + 概率校准（推荐）

```
新闻 → Ontology提取event_type → 历史数据校准LR → 贝叶斯更新先验 → 概率输出 → Kelly仓位
```

- 优点：有学术验证（IARPA范式）、可解释+统计基础、概率可量化
- 缺点：需要构建校准数据集、初期人工标注、实现复杂度最高
- **评估：** 唯一有科学证明可以战胜预测市场的路线

### 路线对比

| 维度 | A（当前） | B（竞品） | C（推荐） |
|------|:---:|:---:|:---:|
| 概率校准 | ❌ | ⚠️ 不稳定 | ✅ 统计校准 |
| 覆盖度 | 低 | 高 | 中（可由B补完） |
| LLM成本 | 零 | 高 | 低（仅边界case） |
| 可解释性 | ✅ | ❌ | ✅ |
| 学术验证 | ICBe（编码层） | 无 | IARPA（全链路） |
| 数学基础 | 离散二分 | 不可靠连续 | 贝叶斯+校准 |

## 6. 当前缺口分析

### 6.1 系统架构缺口

```
Layer 1: Signal Encoding     →  新闻→结构化事件        ✅ 已有
Layer 2: Evidence Weighing   →  评估方向+强度            ⚠️  有但不校准
Layer 3: Probability Update  →  贝叶斯更新概率估计        ❌ 缺失
Layer 4: Aggregation         →  多信号源融合+极端化       ❌ 缺失
Layer 5: Calibration Check   →  历史回测验证校准质量      ❌ 缺失
Layer 6: Execution           →  自动下单+风控            ❌ 缺失
```

### 6.2 Gold Sample 问题

- 当前仅 12 条人工构造 case
- 全部为理想场景，未接触真实 Polymarket 数据
- "12/12 passes" 等于自己出卷子自己打分
- 需要：至少 100+ 个真实市场的信号-vs-结果配对

### 6.3 代码缺口

| 模块 | 代码量估计 | 核心难度 |
|------|:---:|:---:|
| 历史价格数据采集+存储 | ~200行 | 低 |
| 纸面交易模拟器 | ~300行 | 低 |
| Brier分数追踪（per event_type） | ~150行 | 低 |
| 贝叶斯更新引擎 | ~200行 | 中 |
| Likelihood Ratio 校准 | ~300行 | 中高 |
| Kelly仓位计算 | ~50行 | 低 |
| CLOB自动下单（借鉴PolyClaw） | ~200行 | 中 |
| 实盘风控（多层限额） | ~200行 | 中 |

**总计：~1,600 行新代码。无需新增外部依赖。工程可行。**

## 7. 实施路径

### 当前状态评估

- ✅ 市场扫描 + 新闻采集
- ✅ 事件抽取 + Ontology 映射
- ❌ 概率校准（核心缺失）
- ❌ 历史回测（核心缺失）
- ❌ 纸面/实盘交易
- ❌ 风控系统

### 建议实施顺序

| # | 步骤 | 目标 |
|---|------|------|
| **P0** | 拉取伊朗相关已结算市场的价格序列 + 结算结果 | 构建校准数据集 |
| **P0** | 实现纸面交易模拟器（记录虚拟交易+盈亏） | 验证信号质量 |
| **P0** | 计算每个 event_type 的历史方向准确率 | 量化信号有效性 |
| **P1** | 基于历史数据校准 Likelihood Ratio | 实现连续概率输出 |
| **P1** | 实现贝叶斯更新 + Kelly 仓位 | 从信号转为交易决策 |
| **P1** | 纸面交易跑 100+ 个市场，统计 P&L | 验证整个链条 |
| **P2** | CLOB 最小额度实盘（$50-100） | 闭环验证 |
| **P2** | 多层风控（日损10%/回撤20%自停） | 实盘安全 |
| **P3** | 跨市场对冲发现（借鉴 PolyClaw） | 扩展策略 |
